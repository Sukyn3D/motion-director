# 原则与决策

来源索引见 [sources.md](sources.md)。以下“迁移规则”是本 skill 对公开原则的工程化解释，并非公司官方 Web/App 混合规范。

本版采用这些来源的设计语言；覆盖政策以[coverage.md](coverage.md)和SKILL.md为准。原包“用途不足保持静止”的默认策略已改为合格控件全覆盖，强度按用途分配。

## 用途决定表现

| 场景 | 默认模式 | 视觉重点 | 应避免 |
|---|---|---|---|
| 输入、按钮、切换、连续列表操作 | productive | 即时反馈、稳定目标、短恢复 | 前摇等待、夸张回弹、每次重播 |
| 抽屉、弹窗、卡片详情、导航交接 | productive / 轻度 expressive | 来源、目的地与空间连续 | 改变方向、突跳、丢失焦点 |
| 重要完成、首次引导、品牌交互 | expressive | 一个清楚的主动作、有限跟随 | 多个主角、漫长庆祝挡住下一步 |
| 官网宣传、作品、故事滚动 | narrative | 构图、节拍、视觉记忆 | 强制等待、阅读变成解谜 |

## 各体系提供什么

Apple、Material 3、Disney、Fluent 2与Carbon同层级、同地位，统一入口见[design-foundations.md](design-foundations.md)。五个视角共同决定方案并使用相同的家族评审和采纳方式；表中顺序、篇幅和条目数量不是优先级。WAI要求对全部方案统一生效。

| 体系 | 公开原则摘要 | 本 skill 的迁移规则 | 边界 |
|---|---|---|---|
| Apple HIG / Fluid Interfaces / Springs | 有目的、简洁、响应用户；运动可取消；与手势和速度衔接 | 跟手优先于演出；视图中途转向保持位置与合理速度；高频操作无需额外表演 | HIG 不是统一的毫秒表；原生组件与平台行为优先 |
| Google M3 Expressive | 用 physics scheme；区分 spatial 与 effects；有 standard / expressive 及速度层级 | 空间与透明度采用不同轨道；基础模式一致，关键时刻才强调；改目标不重启 | dampingRatio 不等于 Web 库的 damping；使用框架版本对应的 tokens |
| Disney 动画传统 | 表演可信、注意清楚、动作有节奏与性格 | 在确有表达用途时采用预备、跟随、弧线、压缩等手法 | 角色表演原则不是 UI 合规规范；用户操作不必等待角色式前摇 |
| Microsoft Fluent 2 | 功能、自然、一致、吸引力；按尺寸距离调时序；编排引导注意 | 多元素动作有主次；列表 stagger 受总体完成时间限制；顶级切换可选择轻淡变 | 大面积移动可能暗示错误层级；按信息关系决定 |
| IBM Carbon | productive / expressive 双模式，语义一致，按变化规模定时长 | 相同状态含义使用一致动作；把表达留给低频重要节点 | Carbon 网格路径策略是其系统风格，不是对所有曲线路径的禁令 |
| W3C WAI | 可停止非必要运动；自动持续运动需满足相应暂停规则 | 减少动效是另一套完整呈现；保留状态、焦点和操作 | WCAG 2.3.3 是 AAA，2.2.2 是 A；本 skill 的产品要求不等于自动认证 |

## 按需细节：表演、材质与节奏

Disney官方Animation页支持主次、节奏、重量与表演性等设计依据；完整12原则名称及历史由Frank & Ollie原则页与Disney出版信息核对，官方Animation页并未逐项列齐。表中产品做法是本包适配。以下是Disney视角的内部迁移细节，按任务相关性使用，与其他体系的机制细节同级，共用家族合同与验收。无需额外逐项打卡，不强迫同时使用十二种可见效果。

| 原则 | 在产品中怎样用 | 何时收敛/不用 |
|---|---|---|
| Squash and stretch 压缩伸展 | 用轻微 press 表现接触，装饰图标可表达材质 | 正文、数据和点击区域保持稳定；不要把形变当唯一反馈 |
| Anticipation 预备 | hover/focus/按下先建立可操作信号 | 不给“提交”“返回”等动作增加等待前摇 |
| Staging 演出布局 | 通过来源锚点和主次安排说明变化 | 多区域同时吸睛时，先调整幅度/对比/时序，保留美感价值；删减须有具体冲突证据 |
| Straight ahead / pose to pose 逐帧 / 关键姿态 | 确定可读端点，连续手势中定义交接状态 | 不用漂亮中间帧掩盖缺失的加载/错误状态 |
| Follow-through / overlap 跟随与重叠 | 主容器先到，装饰稍后稳定 | 真实数据、主要控件不延迟到位 |
| Slow in / slow out 缓入缓出 | 对自主过渡设计加减速 | 直接拖拽阶段遵循手指；匀速进度不强加缓动 |
| Arcs 弧线 | 同源容器到真实目的地、带重量的装饰；不为Icon增加独立位移/旋转 | 表格排序、工具界面优先清晰无交叉路径 |
| Secondary action 次要动作 | 小图标确认主动作的成功 | 不把背景动画变成第二主角 |
| Timing 节奏 | 让反馈、理解、稳定三个阶段各尽其职 | 视觉持续时间不充当业务等待时间 |
| Exaggeration 夸张 | 低频完成时刻适度加强可察觉性 | 高频动作、严肃数据与减少动效模式降低表达 |
| Solid drawing 扎实造型 | 在缩放/过渡中维持形体、遮挡和可读性 | 正文避免随容器缩放而变形；优先真实布局 |
| Appeal 吸引力 | 动作与品牌、内容一致，结束姿态清楚 | 可爱、回弹、粒子不自动等于好体验 |

## 冲突处理顺序

用户意图与平台惯例 → 可操作性与可读性 → 语义/空间关系 → 连续性 → 品牌表达。

例如：“提交成功很有仪式感”可让装饰勾号轻回弹，但结果文字立即显示，继续按钮立即可用；“像 Apple 一样跟手”应检查中途反向与释放速度，不能只换成某个 easing；“迪士尼式按钮”可轻 press，但不让每次点击都上演 600ms 的挤压和弹跳。

对“自然”的理解是符合此界面的因果与预期。临界阻尼、短非线性状态过渡可比明显回弹更合适；普通状态不能硬切，减少动效/平台不可控/紧急语义按主规则处理。
