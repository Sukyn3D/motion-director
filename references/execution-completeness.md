# 从读规则到完整执行

用于已授权实现或优化；审查任务保留方案、不擅自修改。每次使用先按范围列真实组件家族、变体和实例，检索对应能力；小任务在工作记录里内联列项，大任务复用既有覆盖合同。只实现一两个明星控件不能视为全范围完成。

| 真实变化 / 对象 | 必须检查并按适用条件落实 | 细节入口 |
|---|---|---|
| 可操作控件 | 出现、hover/focus、press/release/cancel、真实状态与输入替代 | [coverage.md](coverage.md)、[experience-quality.md](experience-quality.md) |
| 标题、正文组、图片、内容UI | 首次出现、下滚可感知渐入上移、退出与上滚重入；实际root和每个变体接线 | [scroll.md](scroll.md) |
| 文案 / 内容使宽高变化 | 旧/新自然尺寸、约束、真实布局owner、邻接位置、打断与尺寸恢复 | [layout-continuity.md](layout-continuity.md) |
| 弹窗、详情、媒体窗口 | 核对源/目标实际视觉素材；选择普通弹出或合格共享图像；关闭后背景位置、滚动与焦点稳定 | [overlays.md](overlays.md) |
| 导航、列表、数据变化 | 真实身份、方向、重排与真值；变化的几何与内容轨道 | [recipes.md](recipes.md)、[patterns.md](patterns.md) |
| 拖动、释放、材料对象 | 真实跟手位置；适合对象的形变、释放、边界与恢复 | [physics.md](physics.md) |
| 已有动效和视觉润色 | 正常速度基线、原有显著反馈、品牌美感；保留强度、深化机制、具体回归证据 | [enhancement.md](enhancement.md) |
| 需要新设计 / 深化的家族 | 案例库检索与实际源码、不同主机制的适配比较、可感知表现 | [reference-libraries.md](reference-libraries.md)、[composition.md](composition.md) |

五套设计依据共用原有家族评审，以上是同一执行流程的入口，不是新的来源权重。只展开当前适用资源。不能为了“完整”把弹性、磁吸、共享图像等无适用条件的技巧强行加给所有控件。

每个适用项须关联真实选择器/业务ID、组件/代码入口、变化触发、呈现owner与验收路径。矩阵沿用 applied / inherited / native-verified / exception / gap；实现状态和 observed / inferred / unknown 证据分开。示例/helper存在、class已添加、读过文档、最终样式正确，均不能替代实际接线或中间呈现。父组覆盖需要核对所有后代，家族抽样通过仍需查其他变体/实例连接。

执行时先修关系断点，再完成其他适用项，最后逐项回查：是否遗漏内容尺寸、滚动正文/图片、关闭恢复、原有反馈强度；是否只改装饰小标签或只改了数值。发现gap继续当前授权实现；若条件确实不足，列具体未完成项与原因，不能默认为不适用。没有运行环境可以交付实现并标为未运行，不能写验证通过或宣称全能力已发挥。

完成以当前任务覆盖与实际效果为准。能力完整使用需要审计、选型、接线与复核共同成立，调用口令只能帮助明确范围，不能保证模型永不漏项。

回查还须包括：反馈是否贴合造型、图像裁切是否误伤叠加文字/按钮、中心与边缘命中是否一致、覆盖层返回是否让组合 hover 轨道分叉、同组是否有未登记的机制差异，以及跨视图同图的几何/裁切/朝向是否连续。普通窗口策略和用户明确禁止的空间飞行须覆盖每个入口及返回，不能凭其它卡片正常豁免人物/视频变体。沿 [interaction-state.md](interaction-state.md)、[layout-continuity.md](layout-continuity.md) 和 [validation.md](validation.md) 执行相关验收。六方案需求沿案例库流程等用户选择后整合；不是在正式页面擅自选其中一个。
