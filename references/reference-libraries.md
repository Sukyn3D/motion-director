# 案例库选型、改造与验证

用于每次网站 / App 动效设计与优化的 Design 阶段；同家族共用一次选型，小任务内联记录。目标是扩大可实现的审美选择，把优秀案例的运动关系转化为当前界面的完整响应。

## 入口与技术栈

| 当前项目 | 优先入口 | 选择依据 |
|---|---|---|
| React / Next 等 React 项目 | [React Bits](https://reactbits.dev/get-started/introduction)、[官方组件索引](https://reactbits.dev/llms.txt)、[源码仓库](https://github.com/DavidHDev/react-bits) | 按项目选择 JS / TS、CSS / Tailwind 变体；以当前组件页和源码为准 |
| Vue / Nuxt | [Vue Bits](https://vue-bits.dev/get-started/introduction)、[源码仓库](https://github.com/DavidHDev/vue-bits) | 按当前 Vue 组件、参数与安装说明选型；两库组件和 API 不假定一一对应 |
| 原生 App、其他 Web 栈 | 两库的可操作预览与源码机制 | 迁移运动意图、分层、触发和规律，使用当前平台实现；保留原技术栈 |

先查官方目录，再进入相关组件。库持续变化，不把当前数量、安装命令或依赖版本冻结为 Skill 规范。获取所需组件源码，依赖以组件当前说明与项目锁文件为准。

## 怎样让参考真正参与设计

1. **带着场景检索。** 从审计得到节点家族、状态、频率、风格、布局端点与输入设备。已有动效检索能深化显露、光感、材质、主次或连续性的机制；缺口检索完整响应的起点。下面名称是搜索线索，当前是否可用由目录确认。
2. **比较适配关系。** 查看相关候选的可操作预览和参数，观察触发、来源、轨道、结束、重复和反向。比较其气质与项目，不凭静态封面、名称或热度推断质量。少量相关候选足够，不设置固定数量配额。比较适用的不同主机制，而非只换同一种鼠标跟随的幅度/颜色；候选搜索服务于当前家族的内容、材质或状态关系。
3. **读所选实现。** 获取实际源码、依赖及样式，确认代码如何驱动状态、测量坐标、清理资源和处理输入。记录路径与版本/提交（可取得时）；标题里的 spring、scroll 或 morph 不能替代机制判断。
4. **选择并改造。** 适配时可直接采用、调整、组合或重写机制。保留能带来特色的核心关系，例如光感随接触展开、内容按阅读关系显露、材料随受力恢复；通过结构、主次和接续深化表现，单改时长/色值不足以说明深化。与已有成熟表现比较后也可 keep 并说明理由。采用片段时按现有 owner 分层，复用真实业务状态、稳定身份与端点。
5. **接入并验证。** 按 [validation.md](validation.md) 在实际页面正常速度查看，再检查中途反向、快速操作与目标设备。评审品牌气质、表现深度和协调，同时确认覆盖与可操作性。官方演示漂亮、代码可编译或自带 reduced-motion 均不能替代接入后的运行证据。

| 场景 | 可检索的机制 / 名称示例 | 适配重点 |
|---|---|---|
| 文字 / 内容出现 | SplitText、BlurText、AnimatedContent、ScrollReveal | 阅读分组、真实滚动容器、双向退出与重入 |
| 表面 / 材质 | GlareHover、SpotlightCard等 | 光感、边缘、材质、稳定命中区与输入替代 |
| 卡片内容 / 图像 / 选择 | 按内容预览、图像显露、展开、选择关系检索；结合包内卡片模式 | 比较不同主机制，按[card-direction.md](card-direction.md)适配 |
| 有空间意义的品牌响应 | Magnet等 | 有条件的选项，不是全部卡片/按钮默认；目标与输入替代稳定 |
| 导航与菜单 | PillNav、GooeyNav、StaggeredMenu | 当前项语义、方向、可反向编排、焦点 |
| 状态与微交互 | SpringCheck、SquishSwitch、GlideSelect | 真实受控状态、内部图形、键盘与取消 |
| 柔软 / 物理对象 | ElasticSlider、ElasticMesh、Lanyard | 合理材料、输入与形变分层、释放和边界 |
| 氛围 / 视觉润色 | Aurora、Particles、Noise | 品牌和美感价值、视觉主次、目标环境负载 |

表格提供搜索方向，不要求每个控件使用这些组件；一个家族选择合适机制后覆盖全部实例。某库没有相应实现时继续检索另一库或包内模式。

## 与现有规则接合

按 [design-contract.md](design-contract.md) 和覆盖清单补齐所选实现的实际缺口：出现与双向滚动生命周期、从当前呈现反向、颜色/透明度与空间分轨、真实状态立即生效；Icon 本身保持局部位置和方向，窗口与附属层按来源连续交接。输入跟随按既有缓动规则处理。还需适配触屏、键盘、动态减少动效、SSR / hydration / 无 JS 可读性，以及实例取消和卸载。这些共用现有验收，不增加某一原则的额外层级。

下面是 2026-10-10 读到的具体差异，用于说明怎样改造；使用时重读实际版本：

- [React AnimatedContent](https://github.com/DavidHDev/react-bits/blob/main/src/content/Animations/AnimatedContent/AnimatedContent.jsx) 的 ScrollTrigger 使用 `once: true`，`disappearAfter` 是计时消失。因此双向滚动任务需要按实际容器补写进入 / 退出 / 重入与反向接续，不能把该参数当视口退出。初始隐藏也要与内容可读的降级方案接合。[Vue 版本](https://github.com/DavidHDev/vue-bits/blob/main/src/content/Animations/AnimatedContent/AnimatedContent.vue) 同样需检查一次播放；采样版本的全局触发器清理应改为实例清理，避免影响同页其他动画。
- [React SpringCheck](https://github.com/DavidHDev/react-bits/blob/main/src/content/Micro/SpringCheck/SpringCheck.jsx) 提供弹簧与填充轨道；采样版本的非指针激活走即时呈现分支。按当前项目正常模式的键盘连续反馈要求适配，减少动效分支另行保留。
- [React Magnet 源码注册项](https://reactbits.dev/r/Magnet-JS-CSS.json) 的采样实现用 CSS transition 跟随，不等同于继承速度的弹簧。若任务需要物理交接，再适配项目现有物理机制与稳定命中层。

## 记录与访问降级

在家族合同中记录 `reference_recipe`：来源链接、候选与选择理由、可取得的版本/路径、核心机制、采用方式、参数/结构/生命周期改动，以及预览/源码/项目运行分别已查看或未查看。同一选择不重复为每个实例写报告。

访问受限时依次尝试官方仓库 / 索引 / 已有可追溯本地代码。仅能读源码时标明未观看官方运行预览，后续用本地实现验收。无可读候选或无合适实现时使用 [patterns.md](patterns.md) 或按项目原创实现，记录原因并继续已授权工作。审查任务和单纯修复已定位的生命周期 bug 可直接查相关实现，无需重新搜全目录。

源码复用时核查当前 [React Bits 许可](https://github.com/DavidHDev/react-bits/blob/main/LICENSE.md) / [Vue Bits 许可](https://github.com/DavidHDev/vue-bits/blob/main/LICENSE.md)，保留适用的版权与许可声明；本次读到 MIT + Commons Clause。第三方组件源码不打包进本 Skill 的可分发模式资产，规则通过链接和原创适配说明提供入口。具体产品采用时依其实际条款与组件版本处理。

本次读到了官方目录、介绍及以上部分源码，浏览器环境未能启动，未完整观看外部交互预览；这些记录是源码诊断，不是审美实测结论。

## 保留案例机制的完整优势

评估核心关系的完整链条：触发/接触→主响应→子层协作→结束→离开/反向/恢复；记录可感知的设计贡献和项目内适配。不是摘取一个 fade、scale、默认时长或组件名字就声称“发挥案例库”。直接采用、组合与原创改造均可；对库里不符合合同的部分补齐，对适合页面的特色关系保留/深化，不能为规避缺陷把所选机制全部削成通用微放大。也不为展示库数量添加无意义依赖或强套其整个布局。

## 用户要求更多方案：六个可比较的交互方向

当用户明确不满意某个动作并请求更多方案，或请求某按钮/卡片多出几个方案，默认提供六个适合当前页面的候选；用户指定数量/形式时服从用户。先定位所指组件的真实结构、形状、文案、品牌、触发与约束，重新检索相关 React Bits / Vue Bits 预览与源码；结合自身设计能力迁移、组合或原创。六个主机制须有实质差异（例如显露边缘、材质光感、表面接触、局部形状交接等按实际适配），不能以同一种动画的六组颜色/时长/幅度凑数，也不强制六种都来自不同库。

在独立、可操作的比较区域/预览中，用相同真实组件、文案、布局端点和场景呈现六方案；正常速度可逐一或同步触发 enter/leave、press/release、状态反向、键盘及减少动效。包括实际 icon/标签/图片层，不能只给文字描述、GIF封面或六个与页面无关的演示。小组件可共享一页，大型交互可用切换/分栏，避免过密缩小导致无法判断。保持正式页面原方案可用，不在用户选择前替换正式实现。

每个方案简述核心机制、来源或原创部分、适配理由和重要取舍，并推荐最匹配者；明确要求用户选择（可指定组合/调整）。选择等待是这个备选流程的必要输入；未回复不能按推荐项或超时默认整合，现有“自动推进实现”不覆盖此选择条件。用户已授权自主选择或已作选择时不重复索取确认。选择后按该方案覆盖相应家族/结构变体与全部实例，补齐状态/输入/覆盖层返回、反向与响应式验收，再整合页面。一般首次设计/小 bug 修复不被强制做六方案。

案例库暂不可访问时按已有降级路径提供可追溯本地机制/原创候选并如实标明，仍需满足差异、适配和交互比较，不伪造已看预览/源码。若无法渲染，提供实现和未运行边界，不能把静态说明称为完成可交互预览。
